# Asset cache release contract

The release build is `K365_RELEASE=1 bundle exec ruby scripts/build.rb`. Cloudflare's native Git deployment still serves the committed `public/` directory; no hosting project, domain, database, personal preference or browser storage schema changes.

The build copies the current JavaScript module graph, stylesheets, WOFF2 fonts and public data JSON into `/assets/releases/<revision>/`, preserving relative imports and data paths. The revision covers sorted relative names and raw generated bytes, including `search.json`. A data-only daily publication therefore changes the directory URL. HTML references and absolute code/data references point to that immutable directory. The manifest at `/assets/release-manifest.json` records each current file's delivered SHA-256 and revision.

Only `/assets/releases/*` receives a one-year `immutable` policy. Legacy JS/CSS/JSON endpoints and canonical HTML revalidate with `public, no-cache, max-age=0, must-revalidate`; old URLs remain for compatibility. Response rules use trailing-slash page patterns, separate from file asset paths, to avoid duplicate Cache-Control values and stay within Cloudflare's 100-rule limit. Fonts and data inside the revision directory never overlap the legacy rules. Existing print/image/ICS policies stay intact because those asset bytes are unchanged by this repair.

The current and two preceding asset directories remain in `public/` to let already-open tabs finish lazy-loading after a deployment. Older directories are removed only by the source build from this dedicated generated namespace. Cloudflare's versioned deployments preserve complete rollback artifacts independently. The daily publisher stages the whole generated `public/` tree atomically rather than only horoscope HTML, so every page references the same new revision.

No service worker or Cache Storage cleanup is introduced. No localStorage, sessionStorage, IndexedDB, calendar data, consent choice or browser preferences are deleted. Cloudflare CDN invalidation is an external release action and must be recorded separately; the build alone does not claim that a purge occurred. Existing browser HTTP cache entries cannot be remotely deleted: new content-addressed URLs bypass their old keys automatically on the next page load.

## Regression checks

- `node --test test/cache-release.test.js` uses a temporary build fixture to prove deterministic revision generation, data-only invalidation, relative module/data resolution, previous-release retention and current output SHA-256 integrity.
- `python3 scripts/audit_site.py --release` checks all generated canonical HTML and linked files, immutable release references, no-cache compatibility endpoints, header rule limits, public sitemap/indexability, module existence and manifest hashes.
- `node --test test/*.test.js` includes the permanent search, calendar, zodiac, name-day and astronomy suites.

The implementation does not assert that physical iPhone or Android devices were tested. Those results belong in the execution report with browser and device evidence.
